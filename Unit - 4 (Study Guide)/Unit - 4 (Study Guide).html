Bootstrap: Fundamentals & Philosophy

What is Bootstrap?

Bootstrap is a front-end toolkit that provides ready-made CSS styles, layout utilities, and JavaScript components to build responsive, mobile-first websites.

Simple Definition: Bootstrap = A toolkit for creating responsive websites quickly
Official Version Advisory Current Version Note

Bootstrap 5.3.8 is the latest stable Bootstrap 5 release listed in the official documentation. Bootstrap 6 is currently an alpha release, so use Bootstrap 5.3.8 for stable classroom examples unless your course specifically requires an alpha version.

• Official Bootstrap documentation • Version information

Why Use Bootstrap?

1. Universal Screen Adaptability

Creates layouts that adapt to mobiles, tablets, and desktops automatically.

2. 12-Column Responsive Grid

Provides a flexible, robust responsive grid system for fluid content alignment.

3. Rich Component Library

Includes ready-made buttons, cards, navigation bars, forms, alerts, and modals.

4. High Developer Velocity

Reduces the amount of custom CSS needed, speeding up production workflows.

5. Deep Customization & Theming

Supports customization using CSS variables and Sass, enabling bespoke enterprise branding without fighting framework styles.

Adding Bootstrap to HTML & Common Classes

The following example uses Bootstrap 5.3.8 through a CDN (Content Delivery Network).

index.html • Bootstrap 5.3.8 CDN Template 
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Bootstrap Example</title>
  <link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/css/bootstrap.min.css" rel="stylesheet">
</head>
<body>
  <div class="container py-4">
    <h1 class="text-primary">Welcome to Bootstrap</h1>
    <p class="lead">This page uses Bootstrap styling.</p>
    <button class="btn btn-success">Click Me</button>
  </div>
  <script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/js/bootstrap.bundle.min.js"></script>
</body>
</html>

Understanding Common Bootstrap Classes

Class Name Purpose & Functional Effect
container Creates a centered responsive content area with automatic horizontal padding.
row Creates a horizontal wrapper in the grid system with negative margins to house columns.
col-md-6 Uses half the row width (6 out of 12 columns) at the medium breakpoint and above.
text-primary Applies the primary theme text color (standard Bootstrap corporate blue).
bg-light Applies a subtle light-gray background to the container or element.
p-3 Adds standard padding (level 3: 1rem / 16px) across all four sides.
mt-4 Adds top margin (level 4: 1.5rem / 24px) to separate sections vertically.
btn btn-primary Styles an interactive element as a standard primary action button with hover states.
img-fluid Makes an image responsive with max-width: 100%; height: auto;.
Architecture Tip: The CSS link is loaded in the <head> to prevent Flash of Unstyled Content (FOUC), while the JS bundle with Popper is loaded just before </body> for rapid page painting.

Bootstrap Grid System & Responsive Breakpoints

The 12-Column Grid Architecture

Bootstrap uses a 12-column grid. Columns can occupy different portions of a row depending on the screen size. Rows must be placed within a container or container-fluid for proper alignment and padding.

HTML • Two-Column Responsive Layout 
<div class="container">
  <div class="row">
    <div class="col-md-6">Left section</div>
    <div class="col-md-6">Right section</div>
  </div>
</div>
Responsive Stacking Behavior

On medium and larger screens, each section takes half the row (6 of 12 columns). On smaller screens (< 768px), these columns normally stack vertically, filling 100% of the mobile viewport.

Responsive Breakpoints Reference

Prefix Typical Breakpoint Target Device Class & Media Query
sm 576px and above Small devices • Landscape phones (@media (min-width: 576px))
md 768px and above Medium devices • Tablets (@media (min-width: 768px))
lg 992px and above Large devices • Laptops & small desktop displays (@media (min-width: 992px))
xl 1200px and above Extra large devices • Standard desktop monitors (@media (min-width: 1200px))
xxl 1400px and above Extra extra large devices • Ultra-wide & 4K displays (@media (min-width: 1400px))

Configuration Note: These are minimum-width breakpoints in Bootstrap's default configuration; they can be customized using custom Sass maps ($grid-breakpoints) during build pipeline setup.

Git & GitHub Basics: Core Concepts

What is Git?

Git is a version control system that records changes to files over time. It helps developers review earlier versions, create branches, and work safely on code.

What is GitHub?

GitHub is an online platform for hosting Git repositories. It supports collaboration through pull requests, issues, code reviews, and project discussions.

Git vs GitHub: Architectural Comparison

Comparison Dimension Git GitHub
Software Type Version control software (VCS command-line tool) Online cloud platform for Git repositories
Connectivity Can work locally without internet access Usually accessed online for collaboration
Core Responsibility Tracks file changes and commits history Hosts code and supports team workflows
Collaboration Features Provides local branches and merges Provides pull requests, issues, and code reviews
The Synergy between Git and GitHub

Developers use Git locally on their computers to track snapshots of code, create experimental branches, and roll back bugs. When ready to share, they push their commits to GitHub, enabling teammates worldwide to review, comment on, and merge changes seamlessly.

What Do These Commands Do?

  • git commit — records staged changes in the local repository.
  • git log — displays commit history and cryptographic hashes.
  • git branch — lists existing branches in the repository.
  • git switch -c — creates and switches immediately to a new branch.

Remote Sync Commands

Create an empty repository on GitHub, then use its actual URL:

• Write clear commit messages.

• Commit small, meaningful changes.

Isolate changes to facilitate rollbacks and pinpoint debugging.

• Do not commit passwords or API keys.

Always use .gitignore and environment variables for secrets.

• Use branches & review changes.

Separate features onto branches and review diffs before merging.

Browser Developer Tools (DevTools) Overview

What are Browser Developer Tools?

Browser Developer Tools (DevTools) are built-in browser utilities used to inspect HTML and CSS, run JavaScript, analyze network requests, and diagnose webpage problems.

They are available in browsers such as Google Chrome, Microsoft Edge, and Mozilla Firefox.

Opening DevTools: Three Standard Methods

Shortcut Key Press F12

Fastest toggle across most desktop browsers.

Context Menu Right-Click → Inspect

Inspects the exact clicked DOM node directly.

Application Menu Menu → DevTools

Available in browser settings / more tools.

Important DevTools Panels Reference

Panel Name Primary Purpose & Engineering Activity

Console View messages, logs, warnings, errors, and execute interactive JavaScript expressions.

Performance Analyze runtime performance, CPU profiling, frame rates, and page rendering cycles.

Debugging Techniques & Error Taxonomy

What is Debugging?

Debugging is the process of locating, understanding, and fixing errors in a program.

Common Types of Errors

Error Type Meaning & Cause Real-World Example
Syntax error Code does not follow the grammar or syntax rules of the programming language. Missing closing parenthesis ) or bracket
Runtime error An exception occurs while the code executes, crashing script execution. Calling a method on null or undefined
Logical error Code executes completely without errors but produces the wrong result. Using + instead of * in price calculations

Common Debugging Techniques (8 Proven Practices)

  • Read error messages carefully: Inspect line numbers & stack traces.
  • Use console.log() to inspect values: Print state variables at runtime.
  • Use breakpoints to pause execution: Freeze code at exact statements.
  • Step through code one statement at a time: Monitor control flows.
  • Inspect variables & call stack: Trace ancestor function calls.
  • Check Network requests: Identify failed API payloads or 404/500s.
  • Reproduce with a small example: Isolate bugs in minimal testbeds.
  • Test the fix after making changes: Perform regression verification.

Example: Finding a Logical Error

Incorrect Code (Logical Bug)
let price = 100;
let quantity = 3;
let total = price + quantity;
console.log(total);
// 103, but expected is 300
Correct Code (Fixed Operator)
let price = 100;
let quantity = 3;
let total = price * quantity;
console.log(total);
// 300 (Correct mathematical product)

Breakpoint-Based Debugging Workflow (6 Essential Steps)

  • 1. Open the Sources or Debugger panel: Navigate to the Sources tab inside DevTools.
  • 2. Open the JavaScript file: Browse the file tree to locate the target application script.
  • 3. Click the line number to set a breakpoint: A blue/amber marker indicates an active pause point.
  • 4. Perform the action that runs the code: Click a button, submit a form, or trigger an event.
  • 5. Inspect variable values: Hover over identifiers or examine the Scope variables panel.
  • 6. Use Step Over, Step Into, or Resume: Carefully follow code line-by-line to pinpoint issues.

Good Debugging Practice & Engineering Philosophy

Fix the underlying cause rather than hiding the error. After a fix, repeat the steps that originally produced the issue and run relevant tests to avoid regressions in related modules.

AJAX: Asynchronous Web Architecture

What is AJAX?

AJAX stands for Asynchronous JavaScript and XML. It is a technique that allows a webpage to send or receive data from a server without reloading the entire page.

Despite the word XML in its name, modern AJAX applications commonly exchange JSON data.

Simple Definition: AJAX = Communicating with a server and updating part of a webpage without a full page reload

Without AJAX vs With AJAX Architectural Workflows

Traditional Workflow: Without AJAX
1. User submits a request (e.g. clicks form submit)
   ↓
2. Browser discards screen & loads a new page
   ↓
3. Server returns the entire page HTML
Result: Jarring screen flicker, wasted bandwidth
Modern Workflow: With AJAX
1. User performs an action (types, clicks button)
   ↓
2. JavaScript sends background request
   ↓
3. Server returns data (JSON)
   ↓
4. JavaScript updates part of the page dynamically
Result: Instantaneous, app-like seamless UI

Where is AJAX Used? Real-World Applications

• Searching Suggestions

Live autocomplete as the user types into search inputs.

• Loading Comments

Fetching comment threads without reloading articles.

• Updating Shopping Carts

Changing quantity and price tallies on e-commerce sites.

• Background Forms

Submitting forms seamlessly without leaving current screen.

• Infinite Scrolling

Loading more social feed items as user scrolls down.

• Live Dashboard Data

Streaming live sports scores, chat, or stock prices.

Unit 4 • 4.3 Modern Fetch API & Handlers

Fetching Data with JavaScript (Fetch API)

Example: Fetching Data with JavaScript — The modern fetch() API is commonly used for AJAX-style requests.

HTML + JS • Async/Await AJAX Implementation 
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>AJAX Example</title>
</head>
<body>
  <h2>User Details</h2>
  <button id="loadBtn">Load User</button>
  <p id="result">Click the button to load data.</p>

  <script>
  document.getElementById("loadBtn").addEventListener("click", async () => {
    const result = document.getElementById("result");
    result.textContent = "Loading...";
    try {
      const response = await fetch("https://jsonplaceholder.typicode.com/users/1");
      if (!response.ok) {
        throw new Error("Request failed: " + response.status);
      }
      const user = await response.json();
      result.textContent = `Name: ${user.name}, Email: ${user.email}`;
    } catch (error) {
      result.textContent = "Could not load user details.";
      console.error(error);
    }
  });
  </script>
</body>
</html>
Network Requirement: This example uses a public demonstration API. It requires an internet connection.

Understanding the Example

  • fetch(url) — sends an asynchronous network request across HTTP.
  • await response.json() — parses the returned JSON string into a native JS object.
  • response.ok — checks whether the HTTP status is in the successful range (200–299).
  • try...catch — handles network failure or parsing errors safely without crashing.
  • textContent — updates the webpage DOM safely without parsing HTML tags.
Benefits of AJAX
  • Avoids reloading the entire webpage.
  • Can make interactions feel faster.
  • Transfers only the required data in many cases.
  • Supports dynamic, app-like user interfaces.
Limitations and Considerations
  • Network connection may fail or be slow.
  • Server may return unhandled errors.
  • Cross-origin requests may face CORS blocks.
  • Must display loading & error states to users.

JSON (JavaScript Object Notation) Syntax

What is JSON?

JSON stands for JavaScript Object Notation. It is a lightweight text format used to exchange structured data between applications, especially web clients and servers.

Simple Definition: JSON = A text format for representing and exchanging structured data

Example of JSON Data Structure

student.json • Standard JSON Payload 
{
  "name": "Rahul",
  "age": 20,
  "course": "BCA",
  "isStudent": true,
  "subjects": ["HTML", "CSS", "JavaScript"]
}

JSON Data Types Reference

Data Type JSON Syntax Example Type Description & Characteristics
String "name": "Rahul" Sequence of UTF-8 characters enclosed strictly in double quotes
Number "age": 20 Integers or floating-point decimals; NO surrounding quotation marks
Boolean "isStudent": true Literal values: strictly lowercase true or false
Null "middleName": null Represents intentional empty or nonexistent value in lowercase
Array "subjects": ["HTML", "CSS"] Ordered list of comma-separated values inside square brackets []
Object "address": {"city": "Ahmedabad"} Unordered collection of key-value pairs inside curly braces {}

Important JSON Rules

  • Property names must be enclosed in double quotes.
  • String values use double quotes (single quotes are illegal in JSON).
  • Numbers do not use quotation marks unless they are intended as text strings.
  • JSON uses true, false, and null in lowercase only.
  • JSON does not support comments (no // or /* */).
  • A trailing comma after the final property or array item is strictly not allowed.

Unit 4 • 4.4 JSON Serialization & Parsing
Module 4.4 • JavaScript Integration

JavaScript Object vs JSON: Stringify & Parse

JavaScript Object vs JSON Text

JavaScript Object (In-Memory)
const student = {
  name: "Rahul",
  age: 20
};
JSON Text (Serialized String)
const jsonText =
  '{"name":"Rahul","age":20}';

Core Distinction: A JavaScript object is an in-memory runtime value with methods and prototypes; JSON is a raw text representation that can be transmitted across networks or saved to storage.

Converting JS Object to JSON

Use JSON.stringify().

JavaScript Code
const student = {
  name: "Rahul",
  age: 20
};
const jsonText = JSON.stringify(student);
console.log(jsonText);
Output: {"name":"Rahul","age":20}

Converting JSON to JS Object

Use JSON.parse().

JavaScript Code
const jsonText = '{"name":"Rahul","age":20}';
const student = JSON.parse(jsonText);
console.log(student.name);
console.log(student.age);
Output: Rahul • 20

Why is JSON Popular?

  • Easy for people to read and write: Clean key-value syntax.
  • Supported by most programming languages: Python, Java, C#, PHP.
  • Suitable for API requests & responses: Compact payload size.
  • Works seamlessly with JavaScript: Native engine support.
Security & Robustness Precaution:

Important: Only parse trusted or validated data appropriately. Invalid JSON causes JSON.parse() to throw a fatal syntax error, so wrap parsing logic inside try...catch blocks.

Example: Calling an API with Async/Await

async function loadPost() {

API vs AJAX vs JSON Matrix

Term Meaning & Exact System Role
API Defines how software components communicate with one another (the interface contract).
AJAX Technique for making asynchronous web requests from the client without page reloading.
JSON Text format often used to exchange data between client and server across the network.
Conceptual Relationship

These terms are related, but they are not interchangeable. An AJAX request may call a web API, and the API may return data formatted as JSON.

API Best Practices (Production Checklist)

• Read the API Documentation

Study endpoints, required headers, query parameters, and auth tokens.

• Handle Unsuccessful HTTP Responses

Provide user-friendly fallback UI when 4xx or 5xx codes occur.

• Validate Data on the Server

Never trust client payloads; enforce strict server-side schema verification.

• Protect API Keys & Secrets

Keep API keys out of public client-side JS when confidentiality is required.

• Use Authentication & Authorization

Enforce OAuth2, JWTs, or session tokens for private data endpoints.

• Respect Rate Limits & Terms

Avoid flooding endpoints to prevent temporary IP bans and service throttling.

UI vs UX Design & Foundational Principles

What is UI?

UI (User Interface) refers to the visible and interactive elements through which a person uses an application, such as buttons, menus, forms, icons, and page layouts.

What is UX?

UX (User Experience) refers to the overall experience a person has while using a product, including ease of use, efficiency, clarity, and satisfaction.

UI vs UX: Core Differences Matrix

Dimension UI (User Interface) UX (User Experience)
Focus Focuses on the interface's appearance and controls Focuses on the overall user journey and experience
Components Includes typography, colors, buttons, and layout Includes usability, navigation, task completion, and feedback
Key Question Asks: "What does the interface look like?" Asks: "How easy and useful is it to use?"

Basic UI/UX Principles (Foundations 1 to 6)

1. Simplicity

Keep interfaces clear and avoid unnecessary elements.

2. Consistency

Use consistent colors, fonts, button styles, spacing, and patterns.

3. Visual Hierarchy

Make important info stand out via size, spacing, contrast & placement.

4. Clear Navigation

Users should understand where they are and how to reach pages.

5. Feedback

Provide visible responses when clicking buttons, submitting, or on error.

6. Accessibility

Design interfaces usable by people with diverse abilities and inputs.

Example: Poor vs Better Form Design

Poor Design (Anti-Pattern)

Missing visible label, ambiguous placeholder, generic submit.

<input placeholder="Enter data">
<button>Go</button>
Improved Design (Accessible & Clear)

Explicit label, email validation constraint, meaningful action.

<form>
  <label for="email">Email address</label>
  <input id="email" name="email"
         type="email" required>
  <button type="submit">Submit</button>
</form>

Design Rationale: The improved example provides a clear label, a suitable input type (type="email" activates mobile keyboards), and a required-field constraint. A complete application should also provide understandable validation feedback.

How to Evaluate UX (5 User-Testing Protocols)

  • Ask users to complete realistic tasks: Test genuine workflows rather than artificial clicks.
  • Observe where they hesitate or make mistakes: Uncover cognitive friction and points of confusion.
  • Check whether labels and messages are understandable: Ensure jargon-free terminology.
  • Test on mobile and desktop devices: Audit touch target sizes, tap responsiveness, and viewports.
  • Improve the design based on evidence and feedback: Iterate based on behavioral observations.

Web Accessibility: Core Concepts & Practices

What is Web Accessibility?

Web accessibility means designing and developing websites so that people with disabilities can perceive, understand, navigate, and interact with them.

Accessibility can benefit people using screen readers, keyboards, voice input, captions, magnification, or other assistive technologies.

Simple Definition: Web accessibility = Making websites usable by people with a wide range of abilities

Why is Accessibility Important?

1. Digital Inclusivity

Makes digital content accessible to all citizens regardless of physical ability.

2. Assistive Tech Support

Enables blind, motor-impaired, and low-vision users to browse independently.

3. Universal Clarity

Improves clarity, readability, and overall usability for every visitor on all devices.

4. Legal & Regulatory Compliance

Helps organizations meet applicable accessibility laws and university guidelines.

Common Accessibility Practices (Practices 1 to 4)

1. Use Semantic HTML

Use elements according to their meaning, such as <header>, <nav>, <main>, <button>, and <footer>. 

<main>
  <h1>Student Portal</h1>
  <button type="button">View Profile</button>
</main>
Prefer a real <button> for actions instead of a clickable <div>.
2. Alternative Text

Provide descriptive alt="..." for images; use empty alt="" for decorative art.

3. Label Form Controls

Explicit <label for="..."> tags. Placeholders are never replacements for labels.

4. Keyboard Navigation

Support Tab/Enter. Never remove visible focus indicators without accessible alternatives.

Accessible Contrast, Heading Order & Form Architecture

Common Accessibility Practices (Practices 5 to 8)

5. Use Sufficient Color Contrast

Text and interactive controls should have enough contrast against their backgrounds. Do not communicate information through color alone (e.g. combine color with icons or text badges).

6. Use Headings in a Meaningful Order

Headings should describe the logical page structure rather than being selected only for visual font size. 

<h1>Web Development</h1>
<h2>Accessibility</h2>
<h3>Keyboard Navigation</h3>
7. Add Captions to Important Video Content

Captions help people who are deaf or hard of hearing and can also help users watching multimedia in noisy environments or without sound.

8. Make Error Messages Clear

Explain what went wrong and how to correct it. Where possible, identify the affected form field explicitly in text.

Programmatic Association & Production Guidance:

The labels are programmatically associated with their inputs via for="id", and required fields are identified with semantic required attributes. A production form should also display accessible instructions and live error messages when validation fails.

WCAG Guidelines & Accessibility Audit Checklist

Accessibility Testing Checklist (8-Point Audit)

  • Can all interactive controls be used with a keyboard?
  • Is keyboard focus clearly visible with high-contrast outlines?
  • Do informative images have appropriate alternative text?
  • Are form fields programmatically associated with visible labels?
  • Is the content readable with sufficient color contrast?
  • Are headings and semantic landmarks structured meaningfully?
  • Are errors clearly explained in text with recovery paths?
  • Has the page been checked with automated tools and assistive technologies?

WCAG: The Four Core Principles (POUR)

WCAG stands for Web Content Accessibility Guidelines. It provides internationally used guidance for making web content more accessible. Its four core principles are often summarized as POUR:

Principle Meaning & Engineering Requirement
P • Perceivable Users can perceive the information (content cannot be invisible to all user senses).
O • Operable Users can operate the interface (interface cannot require interaction a user cannot perform).
U • Understandable Content and behavior are understandable (users must comprehend info and operations).
R • Robust Content works reliably across different browsers, screen readers, and assistive technologies.
Auditing Best Practice:

Automated tools can find some accessibility problems, but they cannot identify every issue. Manual keyboard testing and testing with assistive technologies are also valuable.
